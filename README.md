# 映格 · 电影与在线视频学习工作台

Windows 桌面客户端，支持一键持续自动学习：准备本地模型 → 三站查找与下载 → 分析字幕与连续画面 → 积累动作、表情、景别和节奏参考 → 从小说生成可编辑的 AECPP 动画。也支持手动添加视频链接、本地电影，以及独立的电影时序训练和截图检测训练。

「小说成片」按现有资源组合生成：粘贴文字，点击 **一键生成动画**，自动匹配 AECPP 已有角色 / 动作 / 表情 / 场景，组装可编辑的 `.aecpp`。无需先训练 YOLO，也不使用生成图片再拼视频的流程。

Windows 的「小说成片」默认勾选 **自动配音、口型和音效**：直接复用已安装的中文系统语音，按角色固定声线和语速；仅有一个中文声线时复用声线并用语速区分。配音不联网、不下载模型，不做声音克隆。旁白自动配音但不绑定人物口型；取消勾选可保留无声组装流程，选项随草稿保存。

每句先生成真实语音，再把镜头延长到能容纳完整对白（含前后留白），字幕、角色动作和后续镜头同步调整。口型由真实音频能量生成约每 40 ms 一帧的开合关键点，停顿闭嘴；它是音量驱动的近似开合，不是逐音素嘴型识别。每个角色保留独立口型轨，链接到对应配音音轨，能在 AECPP 中继续调节关键点、移动或裁剪声音。为兼容 AECPP 的音轨数量上限，较大角色阵容共享对白音轨，仍保留各角色的口型包络。

跳跃、摔倒、震惊、开心可自动插入内置短音效，独立于对白并降低音量。工程旁的 `story.assets/sound/` 保留配音、音效、逐句原始 WAV 和 `sound-report.json`；总匹配报告记录声线、语速、时间变化及音效位置。声音失败或取消时不会发布假成功的有声工程，中文声线缺失会给出 Windows 语音包修复提示。单句超过 60 秒或成片超过 1 小时需按章节拆分。

命令行可用 `python story_tasks.py oneclick input.txt --project 工程目录 --with-sound`；Python 的 `generate_animation(..., sound=True)` 同样使用此流程。已有不传声音参数的脚本保持无声生成。

技术选型可参考用户指定的 GitHubDaily；已核对的候选与接入边界记录在 [开源技术参考](OPEN_SOURCE_REFERENCES.md)，候选项目不代表已经集成。

## 一键启动持续自动学习

进入 **自动学习**，点击 **一键启动自动学习**。无需先进入多个设置窗口，程序会按以下顺序执行：

1. 检查 FFmpeg 和语音依赖，连接本机 Ollama；已安装但未运行时隐藏启动服务。复用已安装的 `qwen2.5vl:3b` 和可用 Whisper 模型；缺少时自动下载默认视觉模型与 `tiny` 语音模型，显示真实来源、文件字节与进度。全部检查成功后自动保存本地内容分析、语音转写、画面理解设置。未安装 Ollama 或基础依赖时显示修复办法，修复后再点一次即可。
2. 持续从 **优酷、爱奇艺、哔哩哔哩** 查找沙雕动画和电影，轮换站点优先顺序及校园、职场、反转、人物对话等关键词。自动排除已经发现的链接，每轮默认最多加入 4 个下载任务。
3. 自动下载、入库、复用字幕或转写、理解内容与连续画面、积累节奏和视觉编排参考；电影另外进入既有电影时序训练。自动打开统一的 **学习可视化仪表盘**，显示当前来源、学习阶段、成果曲线和连续帧；来源详情保留逐项地址、字节、速度和错误记录。
4. 正常轮次间隔默认 60 秒；无新结果或检索失败会逐渐延长间隔，最长 15 分钟。下载/分析待办达到 8 项或电影训练正忙时等待现有任务，缓存磁盘不足 2 GiB 时暂停下载与新增查找，空间恢复后继续。轮次数、设置、来源和缓存会保留，不能把“本轮搜索结束”视为影片已经学会。

点击 **停止自动学习** 会停止新搜索及模型准备、暂停下载队列和自动分析，并停止由持续模式提交的电影训练；保留已下载缓存与学习成果。混入人工确认工作的训练批次仍由训练中心控制。关闭详情窗口或切换页面时继续运行；退出应用后不再后台联网，再次打开点击一键启动会复用模型并继续。暂停状态不会仅因查看页面自行恢复。

持续模式遇到优酷 `-6004`、明确会员/私有/地域限制或受保护视频时，将该项保存为 **已跳过**，保留来源、标题和原因，立即继续队列中的其他视频，并释放本轮名额。需要补充素材时，首次约 10 秒后自动补找；连续遇到限制会逐渐放缓，近期受限的站点暂排在其他已选站点之后，5 分钟后恢复常规优先顺序。已发现的受限链接会去重，不反复自动下载；仍受队列数量、暂停和磁盘空间控制。网络超时或普通解析错误保留为可重试失败，不冒充内容受限。

主页、联网详情和学习任务页显示 **本工程累计成果**：有实际学习成果的视频数、完整/部分完成数、字幕节奏参考数、视觉片段与帧数，以及按视频去重的累计跳过数。展开跳过详情可查看最近原因、原视频和检索来源。统计来自持久化结果，重试或重新分析不会重复累加，重新分析暂停/失败仍保留上次已发布成果；删除或更换来源后旧成果会被排除。验证影片单独计数，其参考不计入生成。关闭重开可继续查看历史成果，一键启动时也会识别旧的明确受限失败记录并转为跳过。

**学习仪表盘** 也可从自动学习主页、来源详情或学习任务页打开。约每秒读取当前来源和任务状态；准备、查找、下载、转写、内容、画面、入库按真实正在执行的阶段高亮，允许下载与学习同时进行。两张曲线可分别切换字幕参考、视觉片段、证据帧、已学习视频或跳过视频。统计变化和每分钟观察值保存到工程的 `learning_metrics.sqlite`，重开及迁移工程可保留；首次观察前不补造历史，删改来源引起的下降如实显示。曲线是成果数量，不是大模型训练损失或识别准确率。

画面分析请求发出前，仪表盘即开始按时间顺序循环播放该片段的真实抽样帧，每 650 ms 切换一帧，可暂停或选择历史任务；它是采样预览，不是完整视频播放。显示原片时间、模型、片段序号，模型返回后显示动作、表情、景别、置信度和观察依据，进入下一段时等待新结果并保留上一段观察。镜头时间轴标出全片真实切镜候选、当前分析窗口及当前帧，间隔数据足够时显示镜头中位时长。帧路径、大小和 SHA256 均校验；关闭仪表盘只关闭显示，后台任务继续运行。

仪表盘的 **素材匹配与组合** 页可直接粘贴小说或剧本，点击 **一键生成有声工程**。素材目录留空时自动发现本机 AECPP，使用同一套已有素材匹配与离线配音流程。每个镜头展示实际角色、动作、表情与背景的名称、编号、匹配方式及替代原因，区分视觉学习参考与原文 / 编排规则。详情保留学习片段、置信度、实际应用字段、候选切镜对阅读时长的调整，以及配音后最终镜头时长；景别对应角色缩放与工程变换关键帧。点击 **查看该镜头的学习证据** 可回到准确的原片片段，旧参考更新后会提示重新生成。

生成后自动用 AECPP 原生引擎绘制组合预览，支持暂停、选镜头和拖动时间轴；**播放有声预览** 用系统播放器播放含实际配音、口型、音效的 MP4。预览最多前 30 秒、640×360 / 8 fps，完整可编辑工程保留全部镜头；生成结果自动收起输入区以便观看，点击 **编辑小说与素材** 可继续修改。这里展示的是生成时的匹配记录，重新载入记录时会校验工程摘要；原生工程修改后可单独 **重试预览**，无需重做配音。预览引擎或合成失败时保留已经生成的工程和匹配说明。

预览需要本机 AECPP 的 `out/build/mingw-release/aecpp.exe`，也可通过 `AECPP_ENGINE` 指定引擎路径；同时需要 FFmpeg。生成输出沿用独立的 `creations/animations/.../story.aecpp` 与 `story.assets`，匹配报告、分镜及 `assembly-preview.json` 同目录保存，重开仪表盘会恢复最近结果。关闭仪表盘不会取消正在进行的组装，重新打开可以继续查看进度；生成或渲染期间应用会阻止切换、迁移工程和退出，可先取消当前步骤。

本地模型准备成功前不恢复历史持续学习任务，失败可重试；持续模式的设置保存在工程的 `continuous_learning.json`。持续运行期间模型设置由此入口管理，手动更改模型前先停止自动学习。要迁移工程或整理缓存，先停止并等待当前步骤结束。

### Ollama 分析加速与断点恢复

默认继续使用 Ollama，并启用 **复用校验缓存、支持断点恢复**。在 **视频理解与笔记 → 模型设置** 可关闭缓存，或调整 **Ollama 保留秒数**（默认 300，范围 0–3600；0 表示每次请求后释放模型）。保留模型不会停止或重启用户已有的 Ollama 服务，到期由 Ollama 释放。

成功完成的视觉窗口和字幕内容块会立即形成检查点。批量分析中途暂停、失败或取消后，重试会校验并复用已完成部分；未完成或输出无效的部分重新推理，整批成功后才发布学习参考。视觉证据帧仍按原设置从原片提取、校验并写入新结果目录，取消不会发布半成品，也不会删除历史学习成果。

推理缓存按原片 SHA256、服务地址、Ollama 模型摘要及完整实际请求识别，覆盖提示词、JSON 结构、推理参数、真实帧内容和时间、字幕上下文。模型同名换版本、视频内容、输入帧或提示词变化会使相应缓存失效；模型摘要无法确认时直接分析。读取缓存时重新校验内容摘要和输出格式，未知或低置信度观察保持原值，动画匹配仍执行原有质量门槛。缓存存放在工程的 `video_analysis/inference_cache`，最多 4000 条 / 256 MiB，超额仅淘汰这些可重算文件。

每秒画面变化和全片切镜检测也会校验原片及解码版本后复用；字幕、角色资料及人工校正每次重新读取。原有 Whisper 转写复用保持不变。模型、每段连续帧数量、图片尺寸和识别门槛均未降低。

仪表盘显示分析耗时、视觉 / 文字复用数量及新增推理次数；当前证据帧标明是否来自校验缓存。这里的数量属于本次分析性能，累计学习成果仍按原规则去重。性能记录随 `model_analysis.performance` 保存，包括模型请求耗时和 Ollama 返回的加载耗时。

收益主要来自重复分析和中断恢复：首次分析全新内容仍需实际模型推理。当前实测机器的原 Ollama 服务使用 CPU；独立测试 Radeon 780M 的 Vulkan 路径遇到缓冲区分配限制，因此未自动启用核显配置，也未更改已有服务环境变量。

学习结果自动供同工程的 **小说成片 → 一键生成动画** 使用，最终组合已有 AECPP 素材。这里积累的是可检索的编排参考并拟合字幕时长；不会自动微调视觉或语言大模型。三站网页及下载可用性取决于实际响应，登录要求、访问失败或没有搜索结果会如实显示并退避，不能保证每站每轮都有可下载视频。

## 联网找素材与自动学习

在「自动学习」点击 **联网找素材**。来源目前限定为 **优酷、爱奇艺、哔哩哔哩**，可勾选其中一个或多个；分别填写沙雕动画、电影关键词。每轮默认每类最多找到 3 条、最多加入 4 个下载任务，可调整数量，或关闭自动下载后手动加入所选候选。

界面显示正在访问的实际来源地址、搜索词、视频标题和页面地址，以及下载阶段、已下载字节、总量、速度、剩余时间、学习内容和错误记录。站内公开搜索不可用时会尝试 Bing、Google 的公开索引；候选视频仍严格限于所选三站。验证码、登录限制、动态页面和无结果均如实记录，搜索结束不代表已下载或学习成功。

爱奇艺优先读取移动站使用的公开搜索数据，保留视频时长及单视频标识，过滤明确标为会员或付费的候选。接口明确拒绝“沙雕”关键词时，会显示原错误并尝试“搞笑”同义词，来源地址记录实际请求。下载队列可用搜索返回的标识解析新版播放页，检查完整点播清单后下载；仅有旧链接而没有搜索标识的失败任务，可重新搜索加入。没有台词的视频仍可学习画面，字幕与内容分析缺失会明确显示。

优酷同时读取公开页面的结构化视频卡片，支持编码后的视频 ID；首页回退仍按同一视频卡片的关键词筛选，预告片单独标注。站内验证码、平台限制播放（如 `-6004`）分别记录，不将空页面记成成功检索，也不把找到候选显示成下载成功。

动画下载入库后进入字幕节奏与分镜参考分析；启用画面理解后还会分析连续帧。电影同时提交电影时序训练，使用当前电影学习设置。可选的影片资料无需先人工填写，未确认的演员、角色和剧情信息不会变成人工训练标签。下载完成、字幕分析、画面分析和电影模型训练分别记录；无字幕也能独立分析画面，不会因时序训练完成而显示全部学会。

**停止找素材** 会停止搜索和尚未交接的候选；已经交接的任务在下载队列、自动学习任务或训练中心分别暂停 / 取消。失败项可选择后重试，已缓存资源可复用。关闭窗口后后台继续；退出应用或切换工程后，尚未完成的发现任务需要显式继续。重新打开历史不会自动启动网络搜索。来源记录保存在工程的 `discovery.sqlite`，随迁移包保存。

## 自动编排学习模式

1. 打开「自动学习」，选择 **自动编排学习（推荐）**，勾选完成后学习并添加视频链接。下载完成后自动进入后台分析，无需先手动标注截图；每个下载任务保留提交时选择的学习模式。
2. 点击 **自动学习任务** 查看分析进度、有效字幕样例数量和节奏模型评估。支持暂停 / 继续、取消、失败重试和重新分析；关闭任务窗口不停止后台任务。退出或切换工程会暂停，重新打开后点击继续。
3. 已导入的视频可在任务窗口通过 **添加现有影片…** 加入，无需重新下载。补充或修正字幕、定时剧本后，选择任务并点击 **重新分析所选**。
4. 自动完成后，在「小说成片」生成新故事会读取本工程的字幕节奏与合格视觉参考；确认过的人工编排优先。也可以打开任务的 **参考分镜**，核对动作、表情、角色和镜头，再点击确认学习。长视频的分镜分成多份，可切换分段打开；已有创作草稿会先保存并备份。

已有字幕或定时剧本会直接复用；缺少字幕时，内置语音转写可用本地 Whisper 模型补充真实时间码。应用每秒分析画面明暗分布以提供粗略切镜候选，并从定时文本学习时长。字幕显示时间与语音转写时间各有误差，切镜候选也不是语义场景识别。动作、表情和景别仍需核对，自动分析不会把这些建议写成人工确认的训练标签。人物名称只在剧本匹配提供证据时绑定，其他内容保留为旁白。

无字幕、没有可用语音模型或未识别到对白时，文字分析会提示补充字幕或配置模型；已配置的画面分析可独立继续。内容与画面分析通过已配置模型推理，积累可检索的编排参考，不会微调大语言模型。AECPP 的真实角色素材通过一键生成自动匹配，也可在素材与组装页调整绑定。

自动时长参考独立保存于 `auto_learning/reference.json`，分析证据和待确认草稿在 `auto_learning/`，任务在 `auto_learning.sqlite`；人工偏好仍保存在 `story_learning/director.json`。同一原片分段按整片分组验证，显式「验证集」影片不参与时长模型拟合。独立影片不足时明确显示未独立验证；留出误差未优于规则时不启用新参考。自动参考只在有限范围内调整时长，模型损坏时提示并回退。以上数据随工程迁移包一起保存。

下拉选择 **电影时序训练** 可继续原来的 GRU 流程；旧下载任务和历史模型不会自动改成另一种训练。下载成功、参考分析完成和人工确认学习分别显示，不混为一个状态。

## 内置视频理解：转写、内容分析、画面动作与笔记

已把适合动画学习的 Video Helper 核心流程直接接入本应用的自动学习队列，无需运行 Video Helper 独立服务：**下载 / 导入 → 复用字幕或本地转写 → 分段内容分析 → 提取实际关键帧 → 保存笔记与导图 → 打开参考分镜核对**。

1. 在「自动学习任务」点击 **视频理解与笔记 → 模型设置**。语音转写默认启用；有字幕时跳过转写。首次使用可点击 **下载语音模型**，选择 `tiny`（约 78 MB）、`base` 或 `small`，也可选择已有 faster-whisper 模型目录。模型保存在程序的 `weights/asr/`；普通分析不会自行下载模型。较小模型更快，准确率需自行核对。
2. 要分析剧情、冲突、可能笑点和镜头建议，勾选 **内容分析**，选择本地 Ollama 或兼容接口，填写服务地址后 **检测模型**，选择可用模型并保存。Ollama 通常使用 `http://127.0.0.1:11434`；兼容接口填写包含 `/v1` 的服务根地址。已有影片点击 **重新分析所选**，后续新视频自动使用保存的设置。
3. 在 **学习结果** 查看内容段、原片时间、生成摘要和对应的原始字幕证据。导图节点会联动内容段，本地关键帧显示实际抽取时间。选择内容段后 **生成所选参考分镜**，进入小说成片工作区编辑，再按原流程导出 AECPP。

语音转写使用本地 faster-whisper、CPU int8，支持音轨延迟、分块处理和取消。依赖随 `setup.cmd` 安装，也可单独运行 `.\.venv\Scripts\python.exe -m pip install -r requirements-learning.txt`。内容分析按真实字幕时间分段，模型只生成内容解释，时间码来自原始证据；文字笔记的辅助关键帧每片最多 24 张。独立的画面理解见下文，确实把连续帧发送给视觉模型。

本地 Ollama 模式的文字和图片留在本机；选择远程兼容接口会发送字幕，启用画面理解还会发送抽样帧。API Key 仅保存在当前应用进程内，也可通过设置中指定的环境变量提供，不写入工程或迁移包。模型设置位于 `video_analysis_settings.json`，转写、关键帧和待审核笔记位于 `video_analysis/`，随工程迁移；模型文件需在新电脑重新配置。

下载、转写、内容分析、关键帧和节奏学习分别显示进度。内容模型不可用或返回格式错误时，任务显示「部分完成」并保留有效的字幕节奏结果；不会用规则拼出的摘要冒充模型结果。笔记与生成的摘要分镜保留“待审核 / 非原台词”标记；只有手动确认后的编排才进入个人偏好学习。思维导图目前是按生成内容段组织的层级导航。

### 连续画面 → 人物动作、表情、镜头参考 → 小说分镜

1. 在 **视频理解与笔记 → 模型设置** 勾选 **画面理解**，填写视觉模型。本机 Ollama 可点击 **一键准备视觉模型**，下载 `qwen2.5vl:3b`（约 3.2 GB）；显示模型名称、服务地址和当前文件的真实下载字节，可用主窗口停止按钮取消请求。模型由 Ollama 管理，重新准备可复用已下载内容。普通分析不自动下载。已有兼容视觉服务可直接填写模型。
2. 保存设置，对影片 **重新分析所选**。默认全片均匀抽样 12 个最长 8 秒的窗口，每段最多 3 张不同时间的真实帧，预算可设 1–60。长电影是稀疏抽样，增加预算会增加耗时，不代表逐帧理解了整片。模型输入包含有序帧和重叠的字幕语境；动作必须依据画面变化，脸部不清或表现不一致时允许输出未知。Ollama 文本模型会被视觉能力检查拒绝。
3. 在 **画面动作** 查看时间范围、动作、表情、景别、模型自评置信度、判断依据和连续帧。进度显示正在分析的模型、片段和原片时间。字幕与视觉描述分别保留；无字幕也能分析画面。
4. 打开 **小说成片** 生成新故事。程序按画面描述、字幕上下文与新文本的相似度检索参考，只有置信度不低于 0.75、相似度不低于 0.6 且证据完整的观察才参与建议。动作映射为待机、说话、走、跑、跳、摔、抖动，表情为平静、开心、生气、难过、震惊，景别为全景、中景、特写。明确的原文动作、舞台指令和人工确认偏好优先；保留原文和角色，不把原片剧情或人物复制进来。

镜头节奏优先使用观察段内的切镜间隔；窗口内不足时，可使用同片全片的场景差异检测结果（每秒 4 帧）计算镜头时长中位数。新学习会自动记录；旧参考在“一键生成动画”实际匹配到时自动补全并缓存，每次最多补全 3 部，每部最多等待 60 秒。检测失败保留已学动作和表情并显示原因，不阻止已有素材组装。节奏只把新分镜时长调整到原时长的 ±20%，保留方法、全片/局部范围、原始时间与证据。

短对白会同时检索学习记录中的真实分句，避免长描述稀释匹配信号；仍保持置信度和相似度阈值，无关片段不会强行套用。学到的动作/表情先形成分镜建议，再按真实目录映射到角色的动作 ID、表情 ID；明确动作、人工编排与手动素材选择继续优先。每次生成的 `matching-report.json` 会逐镜头列出采用的影片片段、建议前后变化、实际角色/动作/表情/背景素材、景别及时间，替代素材单独说明。`.aecpp` 中保留可编辑角色、动作片段、表情片段、字幕和时间线。

视觉参考保存于 `video_analysis/visual_references/`，证据帧位于 `video_analysis/visual_frames/`，文件摘要校验用于检测改动。显式验证影片、过期原片、损坏证据和低置信观察不会进入生成参考；这些自动建议始终标为待审核，不写入人工 `director.json`。该参考库按整片来源管理，不把 GRU 的片内时间划分当成独立效果验证。这是视觉模型推理加样例检索，不是视觉模型权重训练；是否能准确理解特定沙雕画风，仍需要查看真实结果并积累人工修正。

接口依据：[Ollama 视觉输入](https://docs.ollama.com/capabilities/vision)、[结构化输出](https://docs.ollama.com/capabilities/structured-outputs)、[模型下载进度](https://docs.ollama.com/api/pull)；默认视觉模型见 [Qwen2.5-VL 官方模型页](https://ollama.com/library/qwen2.5vl:3b)。

## 导入已有 Video Helper 转写

已按 [Video Helper 的真实转写格式](https://github.com/LDJ-creat/video-helper/blob/ab8684a80675ce24b9c1cee07f8cbd10448b640f/services/core/src/core/app/pipeline/transcript_store.py) 实现本地数据桥接。它可在自己的应用中通过本地 faster-whisper 或用户配置的语音服务生成转写；本应用接收已生成的结果，不需要同时运行它的前端或导入其源码。

1. 在 Video Helper 分析与当前工程对应的同一视频，找到其数据目录中的 `<projectId>/artifacts/<jobId>/transcript.json`。
2. 在本应用的「自动学习任务」添加对应影片，等待当前任务结束；选中该影片，点击 **导入 Video Helper 转写…**，选择这个 JSON。文件对话框会标明目标影片，避免根据相似标题猜测绑定关系。
3. 导入成功后自动重新分析，真实 `segments` 的毫秒时间码进入字幕节奏学习；已导入的其他字幕轨和匹配的人工修正会保留。来源摘要、转写引擎、导入记录及 SRT 存在 `auto_learning/imports/`。

桥接校验 `version=1`、`unit=ms`、片段起止时间和文本；文件上限 16 MiB、100000 段。`contentBlocks`、剧情摘要、思维导图不是逐句字幕，不会作为真实对白导入。已有 Video Helper 用户仍可使用这个入口；其 API 的 `results/latest` 没有完整原始转写，因此桥接使用本地产物接口。内置视频理解流程无需此导入步骤。

## 小说 / 剧本 → AECPP 动画

1. 启动应用后打开「小说成片」，粘贴小说片段或导入 TXT、Markdown、Fountain。支持 `小王：台词` 和明确姓名带动作的小说叙述；不能确定身份的代词和对白保持待核对，不虚构人物。小说建议按章节或短片段处理。
2. 点击 **一键生成动画**。程序优先复用素材目录，也会查找工程或应用同级的 `AECPP`；首次未找到时，在 **3 素材与组装** 选择一次 AECPP 或 `assets` 目录。之后无需逐项绑定或选择保存路径。处理时显示当前扫描文件、匹配原因和复制的素材，可取消。
3. 自动匹配优先保留有效的人工选择，再按名称、明确标签和语义别名选择真实素材；缺少某动作时选用该角色已有动作，找不到对应背景时采用现有背景并记录替代说明。角色身份在整段故事内保持一致；有足够角色时尽量避免不同人物共用同一素材。匿名图片不被宣称已理解其内容。
4. 成功后点击 **打开生成目录**。每次独立保存到工程的 `creations/animations/标题-时间-编号/`，含 `story.aecpp`、`story.assets`、`storyboard.json`、`bindings.json` 和 `matching-report.json`。导出创建真正的 Actor 图层、原生动作 / 表情片段、镜头布局和字幕，并复制用到的角色部件、背景及自定义表情嘴型。**工程与同名 `.assets` 文件夹必须一起保留 / 移动**；原素材库不被修改。配音、道具细化及复杂表演可继续在 AECPP 编辑。
5. 满意后使用确认学习操作，把已审阅分镜加入本工程的编排样例。后续生成参考相似文本的动作、表情、镜头和时长；仅保存或导出分镜不会自动训练。视频抽取帧只是学习证据，不会被当作成片素材。

素材目录与人工映射保存在工程的 `aecpp_resource_bindings.json`，本次自动选择及替代原因另存生成目录。旧草稿在开始前自动备份；失败或取消不替换原分镜；重复生成创建新的工程。如果需要细调，可先生成分镜，在 **3 素材与组装** 修改映射，再使用 **用现有素材组装 AECPP**。该手动导出仍严格检查缺失项。

换电脑后可以重新选择素材目录；已导出的 `.aecpp` 与其素材文件夹可独立携带。当前组装支持有骨骼、绑定部件和已保存动作的 `.actor`，资源包中的 GIF / Spine 角色会说明尚不支持。自动替代不等于素材已经具备原动作，例如“摔倒 / 抖动”缺失时会如实记录采用的已有动作，可到 AECPP 继续调整。素材用于建立可用能力清单和绑定关系，不必把整套美术图片拿去训练视觉模型。

原先的图形小人导出保留为次要的 **导出示意草稿**，便于没有素材时预览结构；主要成片入口始终使用现有素材组装。

编排学习与电影时序 GRU 是两个不同任务。新功能以可解释规则生成初稿，并从用户确认的文本—编排样例学习词面相似度，不会把原有电影特征预测模型当成小说语义模型。它不会自行改写剧情、创造笑点或从文字生成新角色美术。样例保存在工程的 `story_learning/`，草稿保存在 `creations/`，随工程迁移包一起迁移。学习样例含文本内容，仅保存在本机。

命令行一键生成（首次可加 `--resources "D:\AECPP\assets"`，不需要映射文件或输出路径）：

```powershell
.\.venv\Scripts\python.exe -X utf8 story_tasks.py oneclick "我的剧本.txt" --project "D:\映格工程\我的工程"
```

也可以使用命令行按已保存映射严格组合现有素材（`--bindings` 可省略，但没有匹配的素材时会报告缺失）：

```powershell
.\.venv\Scripts\python.exe -X utf8 story_tasks.py generate "我的剧本.txt" --project "D:\映格工程\我的工程" --resources "D:\AECPP\assets" --bindings "D:\映格工程\我的工程\aecpp_resource_bindings.json" --output "我的动画.aecpp" --board "我的分镜.json"
```

旧命令仍兼容，用于图形示意草稿和人工偏好学习：

```powershell
.\.venv\Scripts\python.exe -X utf8 story_tasks.py generate "我的剧本.txt" --output "我的动画.aecpp" --board "我的分镜.json"
# 修改并审阅分镜后，学习本次编排；之后生成时传入相同 --project。
.\.venv\Scripts\python.exe -X utf8 story_tasks.py learn "我的分镜.json" --project "D:\映格工程\我的工程"
.\.venv\Scripts\python.exe -X utf8 story_tasks.py generate "下一集.txt" --project "D:\映格工程\我的工程" --output "下一集.aecpp"
.\.venv\Scripts\python.exe -X utf8 story_tasks.py export "我的分镜.json" --output "修改后的动画.aecpp"
```

导出时请选择新文件名，避免覆盖已有 AECPP 编辑成果。

如果要使用自己的角色素材和配音，选择「导出角色剧本」，在 AECPP 的剧本工作台导入 JSON，再绑定角色、动作和语音资源。此格式使用 AECPP 的结构化剧本接口，单次最多 64 个镜头、32 个角色；命令行可添加 `--actor-script` 并将输出扩展名设为 `.json`。示例正文见 `examples/早睡大作战.txt`。

应用默认进入「自动学习」，六个工作区在同一主窗口内切换，底部持续显示后台训练状态。

| 入口 | 用途 |
| --- | --- |
| 自动学习 | 添加视频、选择自动编排或电影时序学习，管理下载队列及自动学习任务 |

## Windows 安装与启动

新电脑安装 [64 位 Python](https://www.python.org/downloads/windows/) 3.11 或更高版本，包含 Tcl/Tk；建议使用本项目已验证的 Python 3.13。安装时启用 Python launcher 和 `Add python.exe to PATH`。不要使用不含 Tk 的嵌入式 Python 包。

安装 Git 后，在终端执行以下命令；也可以从 GitHub 下载源码 ZIP 并解压到可写目录，然后双击 `setup.cmd`。

```powershell
git clone https://github.com/d-c-huang/aecpp-model-yolo.git
cd aecpp-model-yolo
.\setup.cmd
.\start.cmd
```

`setup.cmd` 在程序目录创建独立的 `.venv`，按 `requirements.txt` 安装依赖，并检查 Tk、PyAV、PyTorch 等组件。已有环境会复用；失败时保留错误说明和窗口，不会删除工程或模型。首次安装需要联网，并为依赖和视频预留足够磁盘空间。以后双击 `start.cmd` 即可，更新源码或依赖后重新运行 `setup.cmd`。

只检查现有环境、不重新安装时运行：

```powershell
.\setup.cmd --check
```

指定工程启动可运行 `.\start.cmd "D:\映格工程\我的影片"`。应用默认工程位于当前用户的 `映格工程\默认工程`，与源码和 `.venv` 分开保存。不要从旧电脑复制 `.venv`，在新电脑重新运行安装脚本。

在线视频的画面和声音可能分别下载，需要 **FFmpeg 可执行程序**合并。由 [FFmpeg 官方下载页](https://ffmpeg.org/download.html)进入 Windows builds，解压后把包含 `ffmpeg.exe` 和 `ffprobe.exe` 的 `bin` 目录加入 Windows 用户 `PATH`，重新打开终端和应用，再运行 `ffmpeg -version` 检查。`setup.cmd` 会提示 FFmpeg 是否可见，但不会替你修改系统路径。PyAV 的解码库支持本地读片，不等于已经安装 FFmpeg 命令行程序。

CPU 可以完成电影学习。需要 NVIDIA GPU 时，按 [PyTorch 官方安装选择器](https://pytorch.org/get-started/locally/)选择与本机驱动兼容的版本，在本项目 `.venv` 中执行所给安装命令；将命令中的 `pip` 或 `pip3` 替换为 `.\.venv\Scripts\python.exe -m pip`，随后运行 `setup.cmd --check` 查看 `CUDA available`。安装脚本不自动选择 CUDA 版本。

## 换电脑继续学习与工程迁移

**GitHub 保存程序源码，不包含你的影片、工程、标注、下载缓存、训练权重或导出包。** `git clone` 只安装程序；把学习成果带到另一台电脑，需要单独迁移工程。

1. 在旧电脑先结束下载、截图、训练和缓存整理任务，再选择右上角「工程 → 导出迁移包…」。默认包含电影原片，方便新电脑继续电影学习；原片越多，ZIP 越大。
2. 把迁移 ZIP 复制到新电脑，按上面的步骤安装并启动程序。
3. 选择「工程 → 导入迁移包…」，导入到新的或空的工程目录。之后在「影片资源」核对影片并点击「学习所选」，在「训练中心」查看历史记录。程序会从兼容的已完成模型开始新的学习批次；迁移保留已保存的成果，不会恢复旧电脑正在运行的进程或某个未完成的训练轮次。

导出时可以取消包含原片以减小体积，但这样不能仅凭迁移包完整继续抽帧和电影学习；需要在新电脑重新下载视频或重新导入原片。外部磁盘上的原片也应通过包含原片的迁移包带走；仅复制工程文件夹不会自动复制那些外部视频。

三个导出入口用途不同：

| 导出类型 | 入口与用途 |
| --- | --- |
| 工程迁移 ZIP | 「工程 → 导出迁移包…」；保留工程与学习成果，可包含原片，用于换电脑继续工作 |
| 电影模型 ZIP | 「训练中心 → 导出电影模型」；包含模型、说明与评估，不含原片，不能代替完整工程备份 |
| 学习素材 ZIP | 「人工校正 → 导出学习素材」；已确认截图、标注、字幕和剧本索引，用于其他训练流程 |

通用人物检测权重也不随 GitHub 源码分发。工程迁移会查找历史电影学习使用的检测权重，按内容校验后一起打包，并恢复最近的电影采样率与学习设置；缺失原片或检测权重时会明确提示。首次安装且没有本地权重时，自动电影学习默认关闭人物分布分析，可在「学习设置」中选择本地权重启用。需要截图辅助识别时，提供自己的本地权重，或在允许联网时使用程序支持的初始权重名称。电影时序模型和 YOLO 检测权重是不同模型；当前电影模型输出数值观测预测，尚不能直接生成完整沙雕动画，能力范围见下文。

## 在线视频学习

进入「自动学习」。一行一个链接，可直接粘贴多个视频网页或 HTTP/HTTPS 视频直链，也可导入 TXT 链接清单。加入队列时自动跳过同配置的重复链接，并逐行提示无效链接；视频按顺序在后台读取，仍能切换到「人工校正」继续生成截图、标注和训练。

支持解析器可读取的网页视频、MP4 等媒体文件及有限时长的 HLS/M3U8，默认最高 720p，也可选 480p、1080p 或原始清晰度。网页覆盖范围以 [yt-dlp 支持列表](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md) 为准，网站变化、登录要求或访问限制可能导致个别链接无法读取。当前不读取浏览器登录信息、不处理未结束的直播或整份播放列表。默认尝试获取可用中英文字幕，导入后的字幕同样可以人工纠错。

工作台显示资源统计、任务状态、下载进度、速度、预计剩余时间和已完成的电影学习批次数。可以搜索标题或来源、按状态筛选、用 Ctrl / Shift 多选并右键批量操作。选中资源可查看本地首帧预览、时长、分辨率、大小、来源、字幕结果和处理日志，也可打开原网页、本地视频、视频目录或直接进入标注。链接可以导出为 TXT 以便再次使用。「资源 / 设置」提供缓存管理、电影学习设置与所选影片资料。

「暂停队列」保留已经下载的缓存；「继续队列」会尝试续传，具体取决于来源服务器。失败项可以一键重试，也可取消所选任务后单独重试。「移除记录」只移除队列记录，保留视频、标注和缓存。切换到其他工作区后任务继续执行；退出应用或切换工程时暂停当前队列，重新进入自动学习后可继续。任务记录保存在工程的 `online_jobs.sqlite`，下载日志保存在 `logs/online/`。

视频默认完整缓存到工程的 `online_media/`，也可在缓存管理中指定其他磁盘。下载完成并通过视频检查后才加入电影列表。相同链接及画质、字幕设置会复用有效缓存，缓存完成后可离线标注和训练。相同内容不会重复创建电影，已存在电影沿用首次导入的名称、分组和有效来源。

完成后学习开关按提交时的模式处理资源。选择「自动编排学习」会进入上文的独立分析队列；选择「电影时序训练」时，整批链接全部结束后再统一投喂 GRU，尚有暂停或等待项就继续等待。电影时序任务需要先核对影片资料，现有训练完成后可继续下一批。连续提交保留各次冻结的资料，同片新提交覆盖旧快照。也可以关闭自动学习，仅导入；之后选择资源，按当前模式点击「开始自动学习」或「投喂已完成资源」。只选择验证影片不能单独拟合训练模型。自动分析进度在「自动学习任务」查看，GRU 的过程与评估在「查看训练记录」查看。

## 缓存位置与空间管理

进入主界面的「缓存管理」，也可从自动学习的「资源 / 设置 → 视频缓存与存放位置」跳转。可以查看每份缓存的大小、所在磁盘、剩余空间、完成状态和电影原片依赖，并批量打开目录、删除所选缓存或清理未使用缓存。

切换目录时可以只改变后续下载位置，旧目录仍被记住并可复用；也可以迁移已有缓存。迁移先复制并逐文件校验，再更新电影与在线任务的活动路径，最后移除已确认一致的旧副本。目标冲突或校验失败时保留原文件，不覆盖不同内容。位置配置保存在工程的 `cache_settings.json`；外部缓存目录与工程绑定，不能同时作为另一工程的缓存目录。备份工程时也应备份自行选择的外部缓存。

删除被电影当作原片使用的缓存前，会列出影响并要求明确确认；截图、标注、字幕、影片资料、已有模型和历史训练快照保留，但后续抽帧或再次训练需要从队列重试下载，或重新导入同一原片。未被当作原片的重复缓存可直接清理。下载、训练、抽帧或缓存迁移期间不能同时整理相关缓存；还会检测同工程旧版后台训练进程，不会停止它们。

## 学习前的影片资料

首次打开影片资料时，程序按片名查询 Bing 和 TMDB。也可选择 Google 或百度，点击「查询并填充」重新查找。搜索引擎不可用时会直接查 TMDB，找不到条目时再查 Wikidata / Wikipedia。片名唯一匹配且与已知年份一致时，程序把查到的年份、演员与角色、剧情填入空白字段，附上来源并保存草稿。同名或年份不明确时，可在候选中选择正确的版本。点击「确认资料并继续」后，资料才用于学习。没有完整资料的视频也可以勾选暂缺内容继续。

上传标题可以包含演员名、清晰度和版本说明，例如「周星驰《逃学威龙》(1991) 国语中字」。窗口会提取片名和年份，并在重新打开时重试上次失败的查询。同名版本会列出年份和可读取的主演，双击对应版本即可填入资料。

演员与角色每行写 `角色 | 演员 | 角色别名`，多个别名用逗号隔开；只有演员时可写 `| 演员名`。另有剧情梗概、带起止时间的剧情事件及来源链接编辑页，支持 JSON 导入导出。确认的角色名加入标注角色名单，演员名不会自动当成角色。已学习影片可以修改资料并重新确认，后续学习使用新快照，历史训练保留原资料。

确认资料会实际进入训练：角色别名归一化人工标注与剧本中的角色，演员角色表、剧情梗概和当时的剧情事件转换为单独的文本条件输入。模型仍只预测原有 32 项画面、声音等观测；资料特征不作为预测目标，不靠复述静态资料降低指标。文本使用固定词面哈希，尚不具备语义理解。整片剧情是额外已知先验，带资料验证会明确标为条件预测；定时事件只用于对应历史时刻，不提前注入未来片段。

## 已学影片的再次使用

已学影片可以继续上一兼容模型训练，也可在学习设置里选择从头重新训练；每次保存新批次，旧模型不会被覆盖。通常先补充或纠正字幕、角色、剧情资料及截图标注，再继续学习更有价值。也可继续抽帧标注、导出素材，或在训练记录中用已经保存的验证样本重新评估模型。重复学习不能替代增加其他电影及独立验证影片；不要把曾经参与训练的影片改成验证集来宣称未见影片表现。

## 直接使用整部电影学习

导入电影后，在「影片资源」选择影片并点击「学习所选」。需要自定义训练任务时，可进入「人工校正 → 手动训练…」，默认任务为「整部电影时序学习」。可以选择当前电影或工程内全部电影，不限制角色人数、是否有对白、是否有人物入镜，也不要求先确认截图。程序顺序读取整部影片，再自动分段形成训练窗口，120 秒是内部单段长度，不是影片长度限制。

设置每秒采样帧数、最大训练轮数和设备，准备资料后即可启动。默认每秒 1 帧，可选 0.25–4 帧；更密的采样增加分析耗时。电影学习默认最多 30 轮，提供快速检查 5 轮、标准学习 30 轮、深入学习 80 轮，也可自定义 1–500 轮、初始学习率与连续未改善停止轮数；预设是上限，不承诺越多越好。在线视频的「电影学习设置」只保存后续学习参数，不立即开始训练。人物数量与画面分布分析使用选定的本地 YOLO 权重，也可以取消，仅学习其余观测。声音、字幕或人物检测缺失时会记录缺失标志，保留无对白、无人、风景和动作等所有画面，不把未检测的资源当成确认没有人物。

训练器以真实 PyTorch GRU 学习连续观测并预测下一个采样时刻。当前 32 维输入包括画面颜色与明暗、帧间变化、光流、声音能量、字幕显示、可选人物数量与分布，以及已确认角色和剧本角色数量。角色数量不截断为两人。字幕纠错、剧本匹配和已确认的人物绑定会加入新的训练快照。

这些特征描述可观测变化。字幕显示不等于实际开口，帧差不等于已确认切镜，模型目前不理解台词语义、具体动作、情绪或笑点，也不输出可直接执行的动画分镜。产物是电影时序基础模型，尚不能直接导入 AECPP 现有的 `aecpp-learning-bundle` 接口，后续需要语义事件学习和动画动作适配。

影片沿用导入时的分组。「整部训练」与「整部验证」按整片划分，「按片内时段」按前 80% / 后 20% 划分。训练窗口不会跨影片、片段和训练/验证边界，标准化只使用训练数据。独立电影验证、片内时段验证、没有验证数据会在训练记录中分别标明。验证指标用于选取模型，不能替代额外未见电影的最终测试。

后台学习期间仍可生成截图、修改字幕、确认人物以及导入新电影。点击「投喂最新资源」会冻结点击时的电影及标注，在当前轮结束后开始下一轮。「工程内全部电影」会包含新导入影片。截图批次的「投喂并生成下一批」沿用最近选择的训练任务，默认投喂电影时序学习。原片画面与声音分析缓存可复用，字幕与人工修正每次按新快照重建。特征定义、采样率和检测权重兼容时，追加素材会保留上一模型及其训练集标准化参数继续训练。若历史训练时段进入新的验证集，或格式不兼容，则重新拟合并说明原因。新训练使用范围内的全部资源，避免只记住最后一批。

电影时序训练会自动调整学习率，默认连续 5 轮没有改善时提前停止，可在设置中调整。训练前的模型也参与比较，后续轮次变差时保留原模型。多部训练影片按影片均衡抽样，避免长片压过短片与新增片；验证仍遍历全部留出窗口。每次训练生成新批次，之前的权重不会被覆盖。

「训练中心」显示电影时序任务的影片数、采样点、训练窗口、逐轮损失、验证范围及「保持上一时刻」基线，损失较低不表示动画一定更好。完成后可以「导出电影模型」。每个批次在 `runs/` 中包含以下文件。

点击「查看学习效果」可查看损失曲线、画面/运动/声音/字幕/人物特征的误差，以及相比简单基线的改善或退化幅度。旧模型也可以后台重新评估，评估不会修改权重。缺少验证数据时会明确显示训练集内部检查，基线误差为零时不显示无意义的百分比。

- `movie_temporal.pt` 是时序模型权重及训练集标准化参数。
- `movie_model.json` 说明特征顺序、采样率、模型结构和能力范围。
- `movie_metrics.json` 保存每轮训练与验证损失、基线和最佳轮次。
- `movie_evaluation.json` 保存最佳模型的分项评估和验证范围。
- `movie_sources.json` 保留这一轮冻结的电影来源、字幕、人工标注和确认的影片资料。
- `movie_corpus.json` 与 `movie_corpus.npz` 保存分组和实际训练特征。

导出的 ZIP 包含模型、说明、指标及去除本地路径的 `movie_profiles.json`，保留确认资料和来源，不打包原电影。程序接口 `movie_sequence_model.predict_next(model_path, history, steps=1, profile=None, history_times_ms=None)` 可加载模型，按模型规定的特征顺序和采样率预测数值观测。资料模型可传入确认资料，带定时剧情时还须传历史时间轴；缺资料按缺失条件处理。它不接受剧本直接生成动画。

## 抽取画面

在「影片资源」导入本地电影，进入「人工校正」后点击「生成截图」。用「当前电影」切换各片的截图列表。未打开工程时，数据保存在当前用户主目录下的 `映格工程/默认工程`。也可通过「工程」菜单打开或新建工程。影片原文件只读。旧工程或影片移到新位置时，可重新导入以记住原片路径。

填写指定时间可取该时刻附近的实际视频帧。同一帧再次截图时会直接定位已有截图。留空则按范围抽样，可先用 5 秒一格粗采全片，再用 1 秒或 0.25 秒一格补采指定片段。随机抽样按画面时间和图片内容去重，指定时间截图按实际帧时间去重。同一工程以电影文件内容摘要识别影片。

当前批次的截图都确认后，点击「生成下一批截图」即可续采。应用会复用本次打开工程后该片的抽样数量、范围和采样层级。采样间隔内的候选不足时，会在同一范围内逐帧补找，并按实际帧时间和图片内容跳过已有截图。

左侧按生成批次显示截图缩略图、时间和标注状态。生成后默认展开新批次并选中第一张新截图，旧批次可点击箭头展开查看。旧工程中未记录批次的图片归入「历史截图」。点批次标题或批次里的截图可切换当前批次。选「未标注」可以只看待开始的截图。

在左侧点选截图，或用 Ctrl、Shift 多选，再点「删除截图」。可从「已删除截图」恢复图片及其标注。删除的截图会从正常列表、后续训练和素材导出中移除，已启动的训练继续使用它开始时读取的标注。

多部电影可在首次导入时分别指定「整部训练」或「整部验证」，使验证集包含未见电影。单部电影可按片内时段分组，后续各层沿用首次选择。

## 人物、物件和台词

选中当前电影后，点「人物 / 资料 → 演员表 / 标注角色名单」，每行录入一个角色名。人物与台词窗口左侧会直接显示这份名单，点名字即可选中该角色。画外台词和轨迹确认窗口也可使用这份名单；影片资料中的演员与角色对应表另行保存。

1. 选择「人物」或添加物件类别。在空白处拖动画框，在框内直接拖动可移动，拖角点可缩放。Shift 加拖动可在已有框内创建重叠框。
2. 双击人物框，或选中后点「人物名与台词」。点选左侧演员表中的名字，也可手动输入角色。单选字幕或用 Ctrl、Shift 多选时，台词会自动填入下方编辑区，核对或改写后保存到人物框。无对白的听者只填姓名。多个人同框时分别标注。
3. 台词与该人物框一起保存。移动、缩放及撤销均保留对应关系。删除框会一并删除其绑定，可用「撤销」恢复。每次编辑自动保存草稿。点击「确认图片并继续」查看下一张已有截图，或点击「确认并生成截图」继续采集。
4. 需要机器先画框时，选中批次再点「辅助识别」。它只为该批次里未标注的训练图生成草稿。也可在画面上右键点「辅助识别此图」。对未标注的验证图，可在提示里选择「继续识别」，再人工复核生成的草稿。所选权重未检出人物时，会用本地通用人物权重补检。无检测框的图片保留未标注状态，可再次识别。

## 字幕、剧本与画外发言

导入电影时会自动索引内嵌文字字幕，以及电影同目录下同名或带语言后缀的 SRT、VTT、ASS、SSA，例如 `电影.zh.srt`。在「字幕 / 剧本」中可为当前电影导入独立字幕文件、重新提取原片字幕，或将文字轨另存为 SRT。

选择「导入剧本并匹配」可导入 TXT 或 Fountain 剧本。TXT 每行写 `角色：台词`，也可写 `[00:01:02.500 - 00:01:04.000] 角色：台词` 直接按时间匹配。英文和中文字幕在时间段完全相同且角色匹配明确时可共享建议。还可从同一条字幕的已确认标注中复用角色。无法确定说话人时，可手动选择或输入角色。

双击人物框后，可以直接查看列表里的字幕原文、来源、时间和建议角色。截图时刻没有正在显示的字幕时，列表会显示前后 5 秒内的字幕。选择台词后，编辑区会同步填入文字，有唯一建议角色时也会即时填入角色名。可手动改写台词或角色名。取消选择会移除对应的自动填入原句，已改写的台词仍可继续编辑。烧录字幕可用「识别画面底部字幕」读取，再匹配剧本。OCR 使用 Windows 已安装的识别语言。只有音频的对白可手填。

选择一条导入或提取的字幕后，点「纠正所选字幕」可修改该时间段的字幕文本。修正保存在工程中，后续匹配和导出使用修正后的文本。要改已经绑定的台词或 OCR 结果，可以在标注窗口下方的台词编辑区修改并保存。

说话人没有出现在画面里时，选图后直接点「画外台词 / 旁白 → 新增发言」。选择「画外人物」「旁白」或「来源未确定」，角色名可留空。这里同样可以采用字幕或手填，同一帧可添加多条不同来源的发言。只拍到听者时，可单独给听者的框命名。这些发言支持编辑、删除和撤销，无框画面也可直接确认。

## 连续片段与角色轨迹

「分析片段」可选择电影、起点及最长 120 秒的连续时段，每秒采样 4 次。「角色确认」提供轨迹的首帧、代表帧和末帧裁剪。可以将相似衣着的候选排在一起，勾选同一角色的多条轨迹后命名，也可撤回或更名。这些角色名在本片的单帧标注对话框内可供复用。

## 导出给电影学习模型

点击「导出学习素材」生成可移动的 ZIP。压缩包中包含：

- `frames/` 存放已确认的原始抽帧图片。
- `samples.jsonl` 每行对应一张已确认画面，按电影及实际时间排序。含电影名称和内容摘要、`time_ms`、`sample_interval_ms`、训练或验证分组、图片相对路径以及画面对象。各对象含类别、归一化坐标 `bbox_xyxy`、片内角色名 `character` 和逐句台词 `dialogue`；`object_id` 只在该行画面内标识对象。
- `tracks.jsonl` 每行是一条经人工命名的轨迹，含同一电影摘要、片内角色名、片段、估计镜头编号和采样点。各点依次为毫秒、左、上、右、下，坐标按画面归一化。
- `subtitles.jsonl` 保存工程中已索引的电影文字字幕时间轴，含电影摘要、来源轨、原文及毫秒起止时间。字幕轨本身不含人工确认的说话人归属。
- `scripts.jsonl` 保存导入的剧本台词，包括电影摘要、剧本编号、行号、角色、原文和可选时间码。标注中保留的 `script_refs` 可对应回剧本编号和行号。

每帧的 `frame_dialogue` 保存无框发言，包含来源类型、可为空的角色名及台词。已采用并保留原文的字幕用 `subtitle_refs` 记录来源和字幕显示时间；OCR 只记录采样画面时间。手填或改写的台词按人工标注保存。字幕显示时间可能与实际开口、停声时间有出入。训练切镜时机或反应节奏时，仍需连续镜头和实际切点。

## 截图检测训练与继续投喂

确认带框或台词的训练集截图后，点击「人工校正 → 手动训练…」，将任务切换为「截图检测与台词检索」，选择初始权重、训练轮数和设备。窗口底部会显示训练进度。训练时可以继续导入电影、生成截图、编辑并确认新标注。

进入「训练中心」可查看正在执行和已结束的训练批次、轮次进度、日志、样本数量及检测指标，也可以打开训练产物目录。缺少独立验证集时，页面会将相应指标标为训练集内部检查。

当前批次的截图都确认后，可点「投喂并生成下一批」。应用会保存点击时工程里所有已确认的标注供训练使用，同时续采并打开第一张新截图。如果已有训练在跑，这次投喂会在当前轮结束后使用。新截图确认后可再次投喂。按钮沿用最近选择的训练任务、轮数和设备：电影时序学习默认最多 30 轮；切换为截图检测任务后，未另设参数时默认 5 轮并自动选设备。

在截图检测任务中，通过「投喂最新资源」排队时，下一批训练会在启动时读取已确认截图与类别。检测模型使用上一批完成的权重继续训练。没有新增或修改的已确认样本时会略过排队批次。「停止训练」会停止当前批和排队任务，已确认标注和此前完成的权重可继续使用。

每批产物位于工程的 `runs/` 下，日志位于 `logs/`。含框样本用于 YOLO 目标检测，输出 `fit/weights/best.pt`，可用于客户端的「辅助识别」。人物名和旁白等台词标注用于拟合基于截图特征和文字相似度的检索模型，输出 `context.json`，可通过 `film_learning.search_context` 查询同片的相似标注。只有训练集参与拟合。缺少独立验证图时，检测模型会用训练图检查运行，`completed.json` 记录有无独立验证集。

## 环境与兼容性

安装步骤见前面的「Windows 安装与启动」。Windows PyAV 二进制包自带解码库。已用短视频验证 MP4、M4V、MKV、MOV、AVI、WebM、TS、M2TS、MPG、WMV、FLV 和裸 H.264。辅助识别可使用本地 `weights/yolo11n.pt` 或自选兼容权重。工程包含 `annotations.sqlite`、`frames/`、在线任务、资料和训练记录等；跨电脑优先使用「工程」菜单的迁移包，原片在外部目录时不能只备份数据库。
